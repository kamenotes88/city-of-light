# Help with City of Light

City of Light uses the Project World engine. Maintainer and declared licensor:
Serhii Chumachenko. The official repository is
[kamenotes88/city-of-light](https://github.com/kamenotes88/city-of-light).

## Start with a useful example

Try one project, save your world, and return to it later. Tell us what made it
easier or harder to resume using the [short feedback format](FEEDBACK.md).
A precise confusing step, reproducible bug, clearer instruction or reviewed
translation is useful. Stars and invitation registration are optional.

Use [GitHub Issues](https://github.com/kamenotes88/city-of-light/issues) for
redacted bugs, help, ideas and permission questions. Include the version,
OS/browser/assistant, the step you tried, expected behavior and actual behavior.
Use fictional project names. Do not upload private worlds, full backups,
credentials, customer records, payment details or raw chat transcripts.
There is no response-time or support-level promise for this preview.

## Changes and translations

Describe the user problem and smallest useful change first. Early work focuses
on opening one world, understanding a next step, saving/exporting and returning.
Discuss substantial changes before investing in them. An issue is not a roadmap
commitment or a purchase.

Read the effective [LICENSE](LICENSE), [NOTICE](NOTICE) and
[contribution guidance](CONTRIBUTING.md). The software is restricted
source-available, not MIT or unrestricted open source. Permission for generated
world deliverables is separate from distributing or hosting the reusable engine.
Contribution guidance does not assign anyone's intellectual property.

English and Russian are built in. Other translation packs must be complete
data files with preserved keys, placeholders and allowed markup. State what
language and visual review you actually performed; structural checks alone
do not certify quality.

## Security and respectful participation

Use the private route in [SECURITY.md](SECURITY.md) for suspected vulnerabilities.
Do not disclose exploit details or private data in a public issue. GitHub private
vulnerability reporting is enabled for the official repository; its configuration
was verified on October 11, 2026. Follow that private route for sensitive details.

Keep feedback relevant and respectful. No harassment, identity attacks,
unsolicited promotion, spam or publication of another person's private data.
The maintainer reviews public moderation concerns through GitHub Issues; never
include a confidential complaint or private evidence in a public issue.

## Releases and invitations

Release notes identify the exact version, changes, tested scope and limits.
Local package checks, public delivery and independent user acceptance are
separate. Downloaded files do not update automatically. Free maintained core
updates are separate from any future paid tool; paid access cannot erase a
person's world or saved results.

The local Improvements shelf offers optional references and manual handoffs.
It does not install tools, connect accounts, charge money or create verified
licenses. Report an offer ID/version and the observed step without private
project contents.

An [optional invitation claim](INVITATIONS.md) is a request for review, not a
payment or guaranteed commission. Stars, downloads, registrations and recruitment
alone earn no reward. Future commercial terms must be separately stated and
accepted. There is no automated referral payout service in this preview.
