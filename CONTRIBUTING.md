# Help make the next step clearer

City of Light uses the Project World engine. Start with one real use case:
one project, one goal, one success criterion and one next step. Tell us where
an interface or instruction made you stop. Use [GitHub Issues](https://github.com/kamenotes88/city-of-light/issues)
and the optional format in [FEEDBACK.md](FEEDBACK.md).

For a bug, include the release version, your OS/browser/assistant, the failing
step and a minimal fictional example. Leave out private exports, credentials
and raw AI chat history. Follow [SECURITY.md](SECURITY.md) for vulnerabilities
instead of posting exploit details publicly.

Discuss a code or artwork contribution in an issue first. Small fixes to
installation, preservation, accessibility and clarity are easier to review than
a new platform. Keep the change focused and explain the observed behavior it
fixes. Package CI is separate from independent user acceptance.

Read the effective [LICENSE](LICENSE) and [NOTICE](NOTICE). This is restricted
source-available software, not MIT or Apache open source. Only propose work you
have the rights to contribute. Identify the exact source and license of any
third-party material; do not relicense it as original City of Light work.
Maintainer and contributor must agree the applicable contribution permissions
before outside code or artwork is merged. This guide is not a contributor
assignment or a separate contributor license agreement.

Submitting an issue or pull request does not guarantee acceptance, payment,
a support obligation or permission to use the official brand for a modified
distribution. Be kind and specific. A star is optional; a reproducible example
helps more than a popularity promise.
