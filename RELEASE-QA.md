Scope: `tooling`. `release-check.py` is exported as
`.github/scripts/release-check.py`; `github-ci.yml` is exported as
`.github/workflows/check-preview.yml`. The checker requires no private builder,
source registry, graph, owner profile, Python packages or npm packages.

From the exported customer repository:

```text
python .github/scripts/release-check.py --directory . --public-ready --locales en ru
```

Before publication, run this same checker locally against the fresh isolated
0.15.1 customer-export directory after its real licensed package is built.
It needs only installed Node/Python and loopback networking; it does not need
an account or the private source tree. Passing it still does not establish
public HTTPS delivery or an independent customer's computer.

It checks the actual manifest, archive byte size and SHA256, exact flat ZIP
members, flat/ZIP byte equality, version/profile consistency and legal metadata.
The required distribution plus archive has a 50 MiB budget; compressed expansion
also has a 50 MiB limit. `--public-ready` requires the sixteen-file payload, matching
`EFFECTIVE` / `REVIEWED` metadata, UTF-8 LICENSE/NOTICE with verified manifest
hashes, minimum complete-text sizes, no known draft/placeholders, and a copyright
notice. These mechanical checks cannot confirm authorship, rights, permission,
legal adequacy or absence of an unknown placeholder. The owner must review the
actual legal text and provenance before those metadata states can be assigned.

The checker runs the exported `node setup-world.cjs --verify`, serves only the
already checked release JSON and ZIP on an ephemeral `127.0.0.1` port, and runs
the exported installer into a new temporary directory. It creates one fictional
project from an inline generic answer schema. For 0.15.0 and later it also imports
fictional selected history, preserves unknown dates, repeats without another
award and checks full backup/restore. Repeat checks compare hashes,
nanosecond modification times and world ID. Existing install sentinel files,
modified installed files and a modified customer world must be refused and
preserved. Temporary files are removed; exported input files are read only.
No account, global assistant configuration or extension is connected. The checker
does not request an external URL or download a runtime. It executes the exported
installer/setup code after artifact verification; it is not a sandbox or a network
firewall for arbitrary modified code.

Use `--artifacts-only` for static checks; its output marks runtime checks
`NOT_RUN`. Omit `--public-ready` only to inspect an unpublished preview. That
mode permits inspection of an unpublished compatible payload and provides no
public-ready result; the current checker does not accept old payload layouts.
`--locales en ru` checks locale selection
and preservation, not visual quality or the correctness of translated text.
Pass `--node <path>` if Node is not on PATH.

## CI boundaries and pins

The workflow runs on `push`, `pull_request` and `workflow_dispatch` with only
`contents: read`, without persisted checkout credentials, secrets, dependency
caching, publishing or `pull_request_target`. GitHub's runtime setup actions use
network access to install pinned Node/Python releases; the checker itself uses
only loopback. The runner image `ubuntu-24.04` is maintained by GitHub and can
change; action and tool versions are pinned, but this is not a frozen runner image.
The workflow's existence is not evidence that GitHub Actions has run.
